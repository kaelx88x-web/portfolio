# Daily Portfolio Briefing AI — Design Spec

**Date:** 2026-05-23  
**Feature:** Daily Portfolio Briefing AI  
**Route:** `/ai/daily-briefing`  
**Status:** Approved for implementation

---

## Overview

A daily human-readable portfolio summary generated by Claude, styled as a morning report from an AI financial coach. The system collects live option position data from the moomoo broker service and mock market regime data, packages it as context, and passes it to Claude to generate a fully structured briefing. The page renders the briefing in a premium dark fintech design (Layout C: hero banner + card grid).

This is a read-only advisory feature. No trades are placed automatically. All recommendations require manual user approval.

---

## Architecture & Data Flow

```
moomoo broker service  →  live holdings (options, strikes, expiry, P&L, account info)
market-regime.service  →  mock VIX, index trend, breadth, sentiment, sector trend
        ↓
daily-briefing.service
  - assembles structured context object
  - builds Claude prompt with all portfolio data + market context
  - calls Claude API (claude-sonnet-4-6)
  - Claude returns BriefingResult as JSON
  - service parses, validates, and returns typed result
        ↓
+page.server.ts  →  load() calls service, passes BriefingResult to page
+page.svelte     →  renders Layout C (hero + metrics + alerts + market + decision)
```

**Caching:** Briefing is cached for 10 minutes per session (same pattern as AI Insights). A "Refresh" action busts the cache and regenerates.

**Claude prompt strategy:** Claude receives the full portfolio context in a structured JSON block and is instructed to return a single JSON object matching `BriefingResult`. Tone instructions: beginner-friendly, explain all recommendations, avoid jargon, use simple language.

## Types

Defined inline in `daily-briefing.service.ts` (consistent with `ai-copilot.service.ts` pattern).

```ts
type HealthScore = 'excellent' | 'good' | 'moderate' | 'risky' | 'critical';

type OptionAlert = {
  symbol: string;
  type: 'covered_call' | 'short_put' | 'long_call' | 'long_put';
  severity: 'urgent' | 'info' | 'profitable';
  message: string;
  recommendation: string;
  daysToExpiry?: number;
  strike?: number;
  currentPrice?: number;
};

type MarketRegime = {
  classification: 'bullish' | 'neutral' | 'bearish' | 'high_volatility' | 'risk_off';
  label: string;
  vixLevel: 'low' | 'normal' | 'elevated' | 'extreme';
  vixValue: number;
  breadth: 'positive' | 'neutral' | 'negative';
  sentiment: 'risk_on' | 'neutral' | 'risk_off';
  sectorTrend: 'positive' | 'mixed' | 'negative';
  summary: string;
};

type PremiumCollected = {
  today: number;
  week: number;
  month: number;
  total: number;
};

type FinalDecision = {
  action: string;               // e.g. "Do not open new positions today"
  reasoning: string;            // plain-language explanation
  allowNewPositions: boolean;
};

export type BriefingResult = {
  greeting: string;
  healthScore: HealthScore;
  healthLabel: string;          // e.g. "Moderate"
  healthEmoji: string;          // e.g. "⚠️"
  thetaEstimate: number;
  unrealizedPnl: number;
  premiumCollected: PremiumCollected;
  optionAlerts: OptionAlert[];
  marketRegime: MarketRegime;
  finalDecision: FinalDecision;
  generatedAt: string;          // ISO timestamp
};
```

## New Files

### `src/lib/services/market-regime.service.ts`
Returns a mock `MarketRegime` object. Realistic values that can be replaced with a real market data API later. No external calls in phase 1.

### `src/lib/services/daily-briefing.service.ts`
Main orchestrator:
1. Calls `getBrokerHoldings()` from the existing moomoo broker service to get live option positions
2. Calls `getMarketRegime()` from market-regime.service
3. Builds Claude prompt with full context
4. Calls Claude API via the existing Anthropic SDK pattern used in `ai-copilot.service.ts`
5. Parses Claude's JSON response into `BriefingResult`
6. Returns result with `generatedAt` timestamp

**Cache:** In-memory map keyed by userId + date string, TTL 10 minutes.

### `src/routes/ai/daily-briefing/+page.server.ts`
- `load()` — calls `getDailyBriefing(userId)`, returns `BriefingResult`
- `actions: { refresh }` — clears cache entry and redirects to reload

### `src/routes/ai/daily-briefing/+page.svelte`
Full UI — Layout C:
- **Page header row** — breadcrumb (AI › Daily Briefing) + Refresh button + cache timestamp
- **Hero banner** — date string, greeting, health badge
- **3-column metrics strip** — theta earned, unrealized P&L, premium collected
- **2-column section** — option alerts (left), market regime (right)
- **Wide final decision banner** — red/green/amber tinted based on `allowNewPositions`
- **AI disclaimer** footer

### `src/lib/components/ai/DailyBriefingMiniCard.svelte`
Purely presentational component. Receives a `BriefingResult` (or `null`) as a prop. Shows: health badge, theta today, unrealized P&L, final decision label, and a link to `/ai/daily-briefing`. If `null`, shows a skeleton/placeholder state.

- **Red:** `#f87171` / `#fca5a5` — losses, danger alerts, bearish regime

- **Primary accent:** `#6c8fff` — headings, links, breadcrumb
- **Mobile responsive:** Metrics strip collapses to 1-column on mobile; alerts+market stack vertically below 768px

## Option Alert Detection Logic (via Claude)

Claude is instructed to detect and flag:
- Covered call or short put expiring within 7 days → `urgent`
- Option price within 2% of strike → `urgent`
- Position at 50%, 70%, or 80%+ max profit → `profitable`
- Roll candidate (near expiry, out of the money, risk manageable) → `info`
- Assignment risk (in the money with < 5 days to expiry) → `urgent`

## Error Handling

- If moomoo broker is not connected → briefing shows a warning card and uses portfolio DB holdings as fallback
- If Claude API call fails → page shows error state with a Retry button
- If Claude returns malformed JSON → service catches parse error and returns a minimal safe BriefingResult with `healthScore: 'moderate'` and an error note in `finalDecision.reasoning`

---

## Out of Scope (Phase 1)

- Real-time market data API integration (VIX, breadth, sentiment)
- Persistent daily briefing history / log
- Push notifications / scheduled generation
- Auto-trading or order placement
- User-configurable alert thresholds
